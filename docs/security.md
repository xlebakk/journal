## Матрица прав «роль × действие × чей объект»

Заполняется на этапе 1 (пользователи, сеансы) и дальше по этапам. Каждая строка — параметризованный тест.

| Эндпоинт | Аноним | Ученик | Преподаватель | Администратор |
| --- | --- | --- | --- | --- |
| `GET /api/v1/health` | 200 | 200 | 200 | 200 |
| любой другой `/api/v1/*` | 401 | по матрице | по матрице | по матрице |

## Модель угроз (кратко)

Будет дополнена на этапе 1. Основные риски по приоритету:

1. **IDOR** — подмена ID в запросе. Защита: `for_user()` у каждого менеджера, чужой объект → 404, UUID-ключи.
2. **Исправление оценки учеником** — у ученика нет ни одного изменяющего эндпоинта, кроме пароля, темы и своих сеансов.
3. **Подбор пароля преподавателя** — лимиты по логину и IP, одинаковые ответ и время для несуществующих логинов, 2FA.
4. **Утечка данных несовершеннолетних** — минимум полей, контакты родителей видит только администратор, нет данных в логах.
5. **Подделка аудита** — триггер запрещает UPDATE/DELETE, приложение не суперпользователь БД.
