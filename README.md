# Электронный журнал учебного центра

Группы, ученики, расписание, оценки, посещаемость и пробные тесты. Три роли: администратор, преподаватель, ученик. Веб (PWA) и Android из одной кодовой базы.

Решения — [docs/decisions.md](docs/decisions.md). Безопасность и матрица прав — [docs/security.md](docs/security.md).

**Статус:** готовы этапы 0 (фундамент), 1 (вход и пользователи), 2 (структура и расписание) 3 (журнал) и 4 (кабинет ученика).

- **Вход и пользователи:**
  - вход с определением роли, 2FA для администратора, принудительная смена временного пароля;
  - сеансы с тайм-аутами по ролям, блокировки, аудит;
  - управление пользователями.
- **Структура центра:** учебные годы и модули, справочники, группы с историей состава (перевод и исключение с датой), курсы с ассистентами.
- **Расписание:**
  - шаблон недели, генерация занятий на 4 недели вперёд;
  - конфликты и предупреждения;
  - отмена, перенос, замена, дополнительные занятия;
  - запросы преподавателей;
  - расписание для каждой роли и печать расписания группы.

- **Журнал:**
  - страница занятия: посещаемость в одно касание, до 3 оценок, тема с подсказками, ДЗ, «все присутствуют», «завершить занятие», статус сохранения и отмена за 10 секунд;
  - сетка «ученики × занятия» с вводом с клавиатуры и вкладкой «Темы»;
  - окно редактирования 7 дней, после него — только администратор с причиной;
  - средние баллы и посещаемость считает одна функция на сервере;
  - главная преподавателя: занятия дня, «Не заполнено», «Внимание».

- **Кабинет ученика:**
  - главная: сегодня, новые оценки, ДЗ, сводка по предметам;
  - дневник-разворот со свайпом;
  - оценки «предметы × даты» с подробностями;
  - посещаемость с календарём месяца;
  - профиль с целью;
  - на телефоне — нижняя панель из 5 пунктов.

Пробные тесты, объявления, отчёты, импорт и экраны администратора для аудита и настроек появятся на этапе 5.

## Запуск за 5 команд

Нужны Git и Docker Desktop (или Docker Engine с Compose v2).

```sh
git clone <адрес репозитория> journal && cd journal
cp .env.example .env            # замените все change-me на свои значения
docker compose -f infra/docker-compose.dev.yml up --build
docker compose -f infra/docker-compose.dev.yml exec api python manage.py seed_demo
# откройте http://localhost:5173 и войдите логином и паролем из вывода seed_demo
```

Пароль Redis в `.env` указывается дважды: в `REDIS_PASSWORD` и внутри `REDIS_URL`, значения должны совпадать. `TOTP_ENCRYPTION_KEYS` — ключ Fernet, команда генерации есть в `.env.example`.

## Демо-данные

Команда работает только в разработке (`DEBUG=True`) и только на пустой базе. Она печатает логины и пароли и создаёт:

- 1 администратора, 6 преподавателей и 60 учеников;
- учебный год 2026/2027 с модулями и праздниками;
- 4 группы и 11 курсов;
- бесконфликтный шаблон недели и занятия за 4 недели назад и 4 вперёд;
- по одному примеру отмены, переноса, замены, дополнительной консультации и запроса преподавателя.
- прошедшие занятия проведены, с темами, посещаемостью и оценками; пара последних не заполнена, два ученика в блоке «Внимание».

Что проверить:

1. **Администратор.** При первом входе настройте 2FA и сохраните резервные коды. Дальше:
   - в разделе «Расписание» посмотрите неделю, фильтр по группе и печать;
   - отмените или перенесите занятие — сервер не даст создать пересечение;
   - в «Шаблоне недели» измените слот — сначала появится список затронутых дат.
2. **Преподаватель.** На главной — занятия дня, «Не заполнено» и «Внимание». В «Журнале» — сетка с вводом с клавиатуры; на странице занятия можно отметить посещаемость, поставить оценки и завершить занятие. Оценки старше 7 дней заблокированы. В расписании видит только свои занятия, занятия, где он ассистент, и замены. Может попросить отменить или перенести занятие; запрос появится у администратора в разделе «Запросы».
3. **Ученик.** На главной — занятия сегодня, новые оценки и ДЗ; в «Дневнике» — неделя с темами, ДЗ и оценками; в «Оценках» — таблица с подробностями по клику; посещаемость — из главной и меню штампа. Видит расписание только своих групп, с пометками «отменено», «перенесено с …», «замена: …». По адресу `/admin/...` видит «Страница не найдена», API отвечает 403.

## Разработка без Docker

Нужны PostgreSQL 16+ (с ICU- или UTF-8-локалью, не `C`), Redis 7+, [uv](https://docs.astral.sh/uv/) и Node 22+.

```sh
cd backend && uv sync && uv run python manage.py migrate && uv run python manage.py runserver
cd frontend && npm ci && npm run dev
```

Переменные окружения те же, что в `.env.example`. Для локальной базы: `DB_HOST=localhost`, `REDIS_URL=redis://:пароль@localhost:6379/0`.

## Проверки

```sh
cd backend  && uv run pytest --cov && uv run ruff check . && uv run mypy . && uv run bandit -q -c pyproject.toml -r apps config && uv run pip-audit
cd frontend && npm test && npm run lint && npm run typecheck && npm run contrast && npm run build && npm audit
uv run --project backend pre-commit run --all-files
```

**e2e (Playwright).** Нужен PostgreSQL с пустой базой `journal_e2e`, Redis не нужен. Playwright сам поднимает Django на `:8001` и Vite на `:5174`, перед каждым прогоном пересоздаёт базу и проходит сценарии: вход каждой ролью, 2FA, создание пользователя, принудительная смена пароля.

```sh
cd frontend && npx playwright install chromium && npm run e2e
```

**API-типы.** После изменения API перегенерируйте схему и типы, CI сверяет оба файла:

```sh
cd backend && uv run python manage.py spectacular --settings=config.settings.test --file ../frontend/src/shared/api/schema.yml
cd frontend && npm run api:types
```

Всё это же запускает CI (`.github/workflows/ci.yml`) на каждый push и pull request.
