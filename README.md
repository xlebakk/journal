# Электронный журнал учебного центра

Группы, ученики, расписание, оценки, посещаемость и пробные тесты. Три роли: администратор, преподаватель, ученик. Веб (PWA) и Android из одной кодовой базы.

Решения — [docs/decisions.md](docs/decisions.md). Безопасность и матрица прав — [docs/security.md](docs/security.md).

**Статус:** готовы этапы 0 (фундамент), 1 (вход и пользователи), 2 (структура и расписание), 3 (журнал), 4 (кабинет ученика), 5 (администрирование и аналитика), 6 (PWA и Android) и 7 (продакшен); этап 8 — приёмка по критериям SPEC §15 (все проходят в CI: Lighthouse 100, Observatory A+, ZAP без FAIL). Дальше — пункты SPEC §16: этап 9 — отзывы преподавателя, этап 10 — подписка на расписание в календаре (iCal), этап 11 — второй язык интерфейса (узбекский, латиница), этап 12 — оплаты.

- **Вход и пользователи:**
  - вход с определением роли, 2FA для администратора, принудительная смена временного пароля;
  - сеансы с тайм-аутами по ролям, блокировки, аудит;
  - управление пользователями.
- **Структура центра:** учебные годы и модули, справочники, группы с историей состава (перевод и исключение с датой), курсы с ассистентами.
- **Расписание:**
  - шаблон недели, генерация занятий на 4 недели вперёд;
  - конфликты и предупреждения;
  - отмена, перенос, замена, дополнительные занятия;
  - запросы преподавателей;
  - расписание для каждой роли и печать расписания группы;
  - подписка на своё расписание в Google Календаре, календаре iPhone или Outlook: личная ссылка в профиле, перевыпуск и отключение.

- **Журнал:**
  - страница занятия: посещаемость в одно касание, до 3 оценок, тема с подсказками, ДЗ, «все присутствуют», «завершить занятие», статус сохранения и отмена за 10 секунд;
  - сетка «ученики × занятия» с вводом с клавиатуры и вкладкой «Темы»;
  - окно редактирования 7 дней, после него — только администратор с причиной;
  - средние баллы и посещаемость считает одна функция на сервере;
  - главная преподавателя: занятия дня, «Не заполнено», «Внимание»;
  - отзыв преподавателя раз в модуль (вкладка «Отзывы»): 2–3 предложения на ученика; ученик видит его в «Оценках», родители — в сводной ведомости.

- **Кабинет ученика:**
  - главная: сегодня, новые оценки, ДЗ, сводка по предметам;
  - дневник-разворот со свайпом;
  - оценки «предметы × даты» с подробностями;
  - посещаемость с календарём месяца;
  - профиль с целью;
  - на телефоне — нижняя панель из 5 пунктов.

- **Пробные тесты:**
  - тест по предмету для одного или нескольких курсов, с разделами или без; итог — сумма разделов;
  - ввод баллов таблицей и импорт из XLSX/CSV с предпросмотром ошибок;
  - среднее, медиана, распределение, сравнение групп и разделов; динамика по центру;
  - у ученика — график в % от максимума с баллами и пунктиром цели по предмету.
- **Объявления:** для всех, для роли или для групп; закрепление и срок показа; на главной ученика и «Сегодня» преподавателя.
- **Отчёты:** ведомость курса (экран, печать, XLSX, CSV); успеваемость и посещаемость по группе, предмету и периоду; заполняемость журналов; сводная ведомость ученика для родителей на одном листе.
- **Администрирование:**
  - импорт учеников по шаблону: предпросмотр с ошибками по строкам, затем одна транзакция;
  - карточки доступа A4 по 8 штук с QR;
  - обзор: занятия дня, незаполненные журналы, низкая посещаемость, блокировки входа, последние события аудита;
  - аудит с фильтрами, видом «было → стало», выгрузкой и журналом входов;
  - настройки центра, логотип, статус бэкапа.
- Выгрузки персональных данных и изменение настроек требуют повторного ввода пароля.

- **Оплаты:** цена группы в месяц и скидка ученика в %; кнопка «начислить за месяц», приём оплаты, аннулирование с причиной; должники в обзоре; ученик видит свой долг на главной и в «Оплате».
- **Языки:** русский и узбекский (латиница). Переключатель — на странице входа и в профиле; выбор запоминается на устройстве.

- **PWA и Android:**
  - сайт ставится на телефон как приложение (manifest, иконки, service worker кэширует только оболочку; без сети — экран «Нет соединения»; на iPhone — подсказка, как установить);
  - Android-приложение на Capacitor из того же кода: вход по токенам (access на 10 минут в памяти, refresh на 30 дней в Android Keystore с ротацией), системная кнопка «Назад»;
  - сеанс телефона виден в «Активных сеансах» и завершается оттуда;
  - сборка подписанного APK — [mobile/README.md](mobile/README.md).

- **Продакшен:**
  - `docker-compose.prod.yml`: Caddy с HTTPS и заголовками безопасности, API без root, PostgreSQL и Redis во внутренней сети;
  - роль БД приложения не может тронуть журнал аудита;
  - еженочный зашифрованный бэкап вне сервера с ротацией 14 / 8 / 12 и ежемесячной проверкой восстановления;
  - структурные журналы;
  - в обзоре — всплески отказов в доступе и входы администраторов с новых устройств.

  Как поставить на сервер — [docs/deploy.md](docs/deploy.md); как начать учебный год — [docs/admin-guide.md](docs/admin-guide.md).

## Запуск за 5 команд

Нужны Git и Docker Desktop (или Docker Engine с Compose v2).

```sh
git clone <адрес репозитория> journal && cd journal
cp .env.example .env            # замените все change-me на свои значения
docker compose -f infra/docker-compose.dev.yml up --build
docker compose -f infra/docker-compose.dev.yml exec api python manage.py seed_demo
# откройте http://localhost:5173 и войдите логином и паролем из вывода seed_demo
```

Пароль Redis в `.env` указывается дважды: в `REDIS_PASSWORD` и внутри `REDIS_URL`, значения должны совпадать. `TOTP_ENCRYPTION_KEYS` — ключ Fernet, команда генерации есть в `.env.example`.

## Демо-данные

Команда работает только в разработке (`DEBUG=True`) и только на пустой базе. Она печатает логины и пароли и создаёт:

- 1 администратора, 6 преподавателей и 60 учеников;
- учебный год 2026/2027 с модулями и праздниками;
- 4 группы и 11 курсов;
- бесконфликтный шаблон недели и занятия за 4 недели назад и 4 вперёд;
- по одному примеру отмены, переноса, замены, дополнительной консультации и запроса преподавателя.
- прошедшие занятия проведены, с темами, посещаемостью и оценками; пара последних не заполнена, два ученика в блоке «Внимание».
- 5 пробных тестов (математика для двух вечерних групп, английский с разделами) и один предстоящий; цели учеников группы 11-М по математике и английскому;
- объявления: для всех, для учеников, для преподавателей, для группы и одно истёкшее;
- отзывы преподавателей за «Модуль 1» — на четверых учеников каждого курса;
- цены групп, две скидки, начисления с сентября и оплаты: каждый четвёртый ученик должен за текущий месяц, один — за два.

Что проверить:

1. **Администратор.** При первом входе настройте 2FA и сохраните резервные коды. Дальше:
   - в разделе «Расписание» посмотрите неделю, фильтр по группе и печать;
   - отмените или перенесите занятие — сервер не даст создать пересечение;
   - в «Шаблоне недели» измените слот — сначала появится список затронутых дат;
   - «Обзор» — незаполненные журналы по преподавателям и ученики ниже порога посещаемости;
   - «Пробные тесты» — сравнение групп по тесту и динамика по центру; «Отчёты» — успеваемость, заполняемость, выгрузка в XLSX (спросит пароль);
   - «Импорт» — скачайте шаблон, загрузите его и распечатайте карточки доступа;
   - в карточке ученика — цели по предметам и «Сводка для родителей»;
   - «Оплаты» — должники, карточка ученика с историей, приём оплаты и аннулирование; во вкладке «Цены и начисления» — цены групп и кнопка «начислить за месяц».
2. **Преподаватель.** На главной — занятия дня, «Не заполнено» и «Внимание». В «Журнале» — сетка с вводом с клавиатуры и вкладка «Отзывы» (выберите период «Модуль 1»); на странице занятия можно отметить посещаемость, поставить оценки и завершить занятие. Оценки старше 7 дней заблокированы. В расписании видит только свои занятия, занятия, где он ассистент, и замены. Может попросить отменить или перенести занятие; запрос появится у администратора в разделе «Запросы». В «Пробных тестах» — результаты таблицей, импорт и статистика; в «Отчётах» — ведомость своего курса.
3. **Ученик.** На главной — занятия сегодня, новые оценки и ДЗ; в «Дневнике» — неделя с темами, ДЗ и оценками; в «Оценках» — таблица с подробностями по клику и отзывы преподавателей (период «Модуль 1»); посещаемость — из главной и меню штампа; в «Тестах» (у учеников группы 11-М вечерняя) — график результатов с целью. Видит расписание только своих групп, с пометками «отменено», «перенесено с …», «замена: …». По адресу `/admin/...` видит «Страница не найдена», API отвечает 403. В «Профиле» (меню штампа) — «Расписание в календаре»: создайте ссылку и добавьте её в календарь по URL; на локальном стенде ссылка вида `http://localhost:5173/api/v1/calendar/…` открывается в браузере как файл `.ics`. Внизу страницы входа — переключатель «Русский / Oʻzbekcha»: интерфейс переключается целиком, вместе с датами.

## Android-приложение

Нужны JDK 21+ и Android SDK. Подробности, подпись и раздача — в [mobile/README.md](mobile/README.md).

```sh
cd frontend && npm ci && cd ../mobile && npm ci
npm run apk:debug     # APK для эмулятора: API на http://10.0.2.2:8000
VITE_API_URL=https://journal.example.com JOURNAL_SIGNING=D:/Android/keys/journal-signing.properties npm run apk:release
```

## Разработка без Docker

Нужны PostgreSQL 16+ (с ICU- или UTF-8-локалью, не `C`), Redis 7+, [uv](https://docs.astral.sh/uv/) и Node 22+.

```sh
cd backend && uv sync && uv run python manage.py migrate && uv run python manage.py runserver
cd frontend && npm ci && npm run dev
```

Переменные окружения те же, что в `.env.example`. Для локальной базы: `DB_HOST=localhost`, `REDIS_URL=redis://:пароль@localhost:6379/0`.

## Проверки

```sh
cd backend  && uv run pytest --cov && uv run ruff check . && uv run mypy . && uv run bandit -q -c pyproject.toml -r apps config && uv run pip-audit
cd frontend && npm test && npm run lint && npm run typecheck && npm run contrast && npm run build && npm audit
uv run --project backend pre-commit run --all-files
```

**e2e (Playwright).** Нужен PostgreSQL с пустой базой `journal_e2e`, Redis не нужен. Playwright сам поднимает Django на `:8001` и Vite на `:5174`, перед каждым прогоном пересоздаёт базу и проходит сценарии: вход каждой ролью, 2FA, создание пользователя, принудительная смена пароля.

```sh
cd frontend && npx playwright install chromium && npm run e2e
```

**API-типы.** После изменения API перегенерируйте схему и типы, CI сверяет оба файла:

```sh
cd backend && uv run python manage.py spectacular --settings=config.settings.test --file ../frontend/src/shared/api/schema.yml
cd frontend && npm run api:types
```

Всё это же запускает CI (`.github/workflows/ci.yml`) на каждый push и pull request.
